- 当前仓库：`github/windhawk-island-liquid-glass/`，基线提交 `00b22c5b1bf05a1df3d8f612a0310abcfbd74b34`，发布版本 `1.4.6`；`original.wh.cpp` 底座标为 `1.3.1`。
- 原版固定到提交 [`7fe506e81e4e72460251aa60110437794dbc88da`](https://github.com/devcode90/Dynamic-Island-for-Windows/commit/7fe506e81e4e72460251aa60110437794dbc88da)，其源码版本标为 `1.4.0`。以下行号均对应此提交的 [`dynamic-island-for-windows.wh.cpp`](https://github.com/devcode90/Dynamic-Island-for-Windows/blob/7fe506e81e4e72460251aa60110437794dbc88da/dynamic-island-for-windows.wh.cpp)。按实际代码确定能力，不把更新说明中的描述当作实现保证。
- 保留现有补丁合成方式、液态玻璃后端、字体回退、紧凑收起样式、首页、独立时钟页、计时器、NBA、重要日子标记、通知、拖动位置和更新机制。

## 已确认的结构差异

| 功能 | 原版实际实现 | 当前接入点与适配重点 |

| 歌词 | `LyricsSnapshot`、`LyricsLines`；LRCLIB 查询、缓存、`LyricsThreadProc`（约 7001–8330 行）；独立页与收起歌词 | `SharedState`、媒体时间线、两套标签绘制分支、`Renderer`、启动/停用线程；原版依赖的新频谱绘制、图片类型和布局需映射到本版 |

两个必须处理的交叉依赖：

1. 原版 `ActiveTabCount` 会动态增加歌词页，还允许歌词置顶；本版另有独立时钟页，且闲置/媒体两套绘制分支的页 ID 不一致。索引必须统一，禁止只在一处加一页。
2. 原版查词聚焦过程调用 `DwmBackdrop::EnsureBehind`，图片与频谱使用 `PixelsRef`、`DrawSpectrum`；本版分别使用自有玻璃后端、`BitmapPixels` 和 `DrawWaveform`，按现有接口适配，不照搬整套渲染器。

## 实施顺序

### 1. 接入歌词与查词必需的共用函数

- 在现有 `build.py` 中接入后续三个功能的新补丁，继续采用唯一锚点断言的补丁方式。
- 仅提取原版实际共用的 UTF-8 转换、原子文件写入，以及歌词/查词所需的 HTTP 状态处理、JSON 字段读取函数。共用头文件在首次使用前注入一次，不新建框架或增加第三方依赖。
- 日历首日、语言和现有文件托盘保存行为均保持原样。后续因歌词页增加而调整日历页身份判断，属于导航兼容修正，不重新引入地区适配。

完成标准：共用函数可供歌词与查词独立使用；没有新增日历地区设置或文件托盘持久化设置。

### 2. 移植跨播放器选择，统一媒体控制目标

- 新增 `media_sources_patch.py`、`media-sources.h`；在当前媒体采集线程接入原版来源收集、稳定顺序、自动选择和用户选择逻辑。
- 保留原版语义：自动模式跟随最近开始播放的来源；Dock 点击为临时选择；右键菜单可锁定来源或恢复自动。临时选择在有新来源开始播放或选中来源消失时结束。
- 来源图标复用本版 `BitmapPixels` 及现有位图绘制、失效机制，不迁入原版全局图片类型。
- 同步适配播放/暂停、前后曲、进度拖动及媒体伴随面板；操作提交时捕获目标来源，执行时重新验证，避免切换过程中控制另一个播放器。
- 来源消失时刷新列表并按自动规则回退，不向无关来源误发已提交操作；同一应用多个媒体会话按原版 AUMID 粒度处理，不承诺逐浏览器标签选择。
- 来源 Dock 放在现有媒体页内部，尺寸和命中区域使用相同几何数据，不改变其他面板的统一展开尺寸；保留与来源切换有关的过渡，不连带换掉整个播放器 UI。
- 菜单命令范围与本版 45–49 等自定义命令隔开，动态来源菜单按明确范围分发，不能用宽泛的 `cmd >= base` 截获其他新命令。

完成标准：两来源同时存在时可选可锁；播放按钮、进度条和画面始终指向同一来源；来源关闭后恢复合理状态，不出现封面残留或失效点击区。

### 3. 移植实时歌词，接入本版标签页与时间线

- 新增 `lyrics_patch.py`，按数据、缓存和绘制拆出 `lyrics.h`、`lyrics-cache.h`、`lyrics-draw.h`，保留原作者许可和来源标注。
- 移植 LRCLIB 精确查询、清理歌名后的查询和候选筛选，支持同步 LRC 与纯文本歌词；缓存保留内存及磁盘两层、容量限制、过期清理和右键清除。
- 只有确实找到的歌词写缓存；超时、限流和服务器失败不缓存为“没有歌词”，界面区分查询失败与曲库无结果。网络请求不放进渲染线程。
- 对 LRC 的一/二/三位小数、同一行多时间戳、无序时间戳增加小型断言；修正原版固定将小数乘十的做法，规范化后按时间排序，保证毫秒同步正确。
- 活动曲目身份包含来源、歌名、歌手、专辑和时长；异步返回校验曲目代次，切换来源或切歌后丢弃旧返回，并清空旧滚动状态。
- 沿用媒体位置估算和用户拖动进度，补齐原版歌词需要的时间线更新；不同歌曲、不同来源不能沿用上一首的防抖状态。
- 保留原版有线/扬声器与蓝牙两组时序偏移及右键微调。在现有音量监听重新绑定默认设备时更新蓝牙标记，只引入歌词校准需要的设备识别，不替换音量面板。
- 完成收起状态当前行、展开歌词专页、同步滚动、高亮、纯文本显示，以及无同步歌词时回到歌名的行为；沿用现有波形与字体回退。
- 将闲置/媒体绘制、页数、滚轮导航、时钟/硬件/托盘索引和命中测试统一到同一页序列。默认顺序保留：主页/媒体、日历、天气（可选）、硬件（可选）、时钟、文件托盘（可选）、歌词（有媒体且开启时）。
- 保留歌词置顶选项；置顶后日历标记等逻辑用页身份判断，清除 `NormalizedTabIndex(...) == 1` 这类受页序影响的条件。歌词页消失时保持当前页身份，当前页本身消失再回主页。
- 原版媒体页内歌词选项也按现有媒体页适配：保留原有控制区和紧凑外观，歌词视图的绘制与点击区域一起变换，不照搬新底座的全局固定画布。

完成标准：暂停不继续滚词、拖进度立即重定位、切歌不串词；开启/关闭歌词以及歌词置顶后，各页绘制、滚轮与日程悬停仍一致；缓存开关独立有效。

### 4. 移植 Quick Lookup，完整处理输入与关闭恢复

- 新增 `quick_lookup_patch.py`、`quick-lookup.h`、`quick-lookup-draw.h`；新增 `IslandKind::Lookup`、查询快照、输入会话和内存最近记录。
- 保留原版来源路由：单词优先英文 Wiktionary，dictionaryapi.dev 备用，再查 Wikipedia；短语先百科，再词典。不扩展翻译或自动单词本功能。
- 默认快捷键 `Ctrl+Alt+Space`，允许设置；保留输入、粘贴、剪贴板候选、最近记录、上下选择、Enter 提交、Esc 关闭及鼠标操作。只在提交查询后发送网络请求。
- 复用本版字体与液态玻璃渲染。查词卡按内容测量高度，保留原版最高 300 逻辑像素的上限和结果行数限制，不强塞进普通 184 高面板；窗口、玻璃区域、命中区域随之匹配。
- 仅查词会话打开时暂时解除 `WS_EX_NOACTIVATE` 并关闭鼠标穿透；关闭、失焦、超时、模块禁用、更新退出时恢复样式，并在适用时归还原前台窗口焦点。
- 查词活动打开时独立显示，避免通知/计时器的次岛与搜索框争夺点击；关闭后恢复现有活动优先级，保留计时器等后台状态。
- 原版 `DwmBackdrop::EnsureBehind` 调用按本版玻璃窗口关系适配，不引入第二套背景窗口；输入消息不得被 Alt 拖岛、Ctrl 穿透、媒体按键和全局隐藏分支提前吞掉。
- 快捷键冲突时保持其他热键正常，记录可定位的错误，不静默换掉用户快捷键；只在所属窗口线程注册与释放。
- 最近记录和查词缓存保持内存保存；保留查询长度上限、请求序号、防旧结果回写和网络响应大小限制。错误与未找到分开，不记录查询正文。

完成标准：快捷键可从自动隐藏状态唤醒；输入与剪贴板候选可查询；Esc/失焦/关闭模块后其他窗口正常输入；连续搜索时旧结果不会覆盖新结果。

### 5. 收束生命周期、构建及使用说明

- 新增歌词和查词网络工作接入现有 `StartThreads` / `StopThreads`。原版查词使用 `std::thread(...).detach()`，歌词 HTTP 超时又可能长于停用等待；不能只复制其 `g_running` 检查或超时后关闭线程句柄的方式。
- 新增请求要可取消，停用时先停止接收任务、使请求代次失效、取消网络等待，再等待新增工作线程真正退出，最后释放事件和句柄。只处理新功能及其必需的共享退出顺序，不扩大为无关线程重构。
- 更新忙碌状态包含查词输入会话和新增任务退出条件；进入更新准备后禁止新开查词。沿用现有手动更新入口、签名与频率，不改更新器脚本或安装器版本。
- 预定补丁顺序：现有 `apply_calendar_markers` 后注入共用函数，再接媒体来源、歌词、查词；现有中文字体注入和 release/updater/drag 仍在其后。根据实际唯一锚点维护必要交接，不取消锚点断言掩盖冲突。
- 相应调整 `expanded_layout_patch.py`、`calendar_markers_patch.py`、`updater_patch.py`、`island_drag_patch.py` 及必要的 `release_patch.py` 锚点。新功能使用同一字号/字体创建入口及资源释放路径。
- 建议新增默认：歌词专页开启、收起歌词和媒体页内歌词由开关控制；查词快捷键开启。仅作为缺省值，保留已有个人设置。
- 更新 `README.md` 与模组内说明，说明媒体会话兼容条件、LRCLIB 元数据请求与本地缓存、查词来源和快捷键。
- 保持本版模组 ID，不自动跨 ID 导入原版个人数据。歌词缓存只在模组存储目录，不进入源码、安装包或发布附件；核对现有升级/回退不会清除该目录，不声称旧版回退会还原所有新文件状态。
- 重新生成可独立编译的发布 `.wh.cpp`；客户端不增加 Python、Token 或新后台服务需求。版本号和正式发布留到用户另行要求发布时处理。

## 待定：文件托盘持久保存

文件托盘是现有的文件快捷入口架子：开启后，把资源管理器中的文件拖到灵动岛，之后可以从托盘点开原文件；拖入只保存引用，不复制或移动真实文件。“持久保存”只让这个入口列表在模组重启或电脑重启后仍在，文件移动或删除后也不会因此恢复真实文件。

当前用户尚不熟悉此功能，先解释用途，未确认加入，暂不实施。若后续选用，再接入原版 `FileTrayStore`、`SaveFileTray`、`LoadFileTray`（约 21120–21360 行）：模组存储目录内按用户保存版本化 UTF-8 列表，复用原子写入，校验容量与损坏文件，关闭保存仅清列表、不动真实文件。
